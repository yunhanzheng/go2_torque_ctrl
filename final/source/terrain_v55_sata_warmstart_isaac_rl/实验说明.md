# V55 — SATA 预训练策略 + IsaacLab 默认奖励，在本地形上微调

## 1. 这个实验回答什么问题

V51–V54 全都继承 SATA 的九项 gs 耦合奖励。上一轮把两边逐项对比后，结论很清楚：

| | V54（现行） | IsaacLab Go2 rough（官方） |
|---|---|---|
| 正项满额 | ≈ **25 /s** | ≈ **2.26 /s**（track_lin 1.5 + track_ang 0.75 + feet_air_time 0.01） |
| 罚项 | 7 项，实测合计 −0.87 /s | 5 项，预估合计 ≈ −0.45 /s |
| 与爬楼冲突的硬罚项 | dof_acc + motor_fatigue + action_rate ≈ −0.79 /s | dof_acc 只剩 −0.08 /s（−2.5e-7 vs −1e-6），无 motor_fatigue |
| 蹭台阶 | undesired_contacts −1.0 | **None** |

也就是说：V54 里"爬楼"这件事被三重税压住，而正向回报主要来自"跟指令速度 + 头部高度恒定"，并不是"上去"。
V55 换成官方奖励表后，硬罚项从 −0.79 /s 降到约 −0.08 /s，正向信号只剩"跟速度"。

那么问题就是：**在 2.3/s 的奖励尺度上，一个从 SATA 拿来的、已经会跑的 actor，还能不能把 23 cm 台阶爬上去？**

V55 与 V54 的唯一差别是 **奖励表 + gs 时钟**，其余（地形、观测、动作、终止、生成状态、PPO）全部继承，
所以这是一次单因子对照。

## 3. gs 怎么处理（结论与理由）

**结论：奖励侧彻底去掉 gs；环境侧 gs 从 0.789 线性升到 1.0（500 iter），之后冻结在 1.0。**

gs 在 SATA 里是一块"总生长表盘"，同时控制四件事：

```
gs = exp(-exp(-k*(step_count - x0)))        k=3e-5, x0=24000
current_freq              = 100 + 100*gs     # 100 → 200 Hz
current_torque_limit_scale= 0.3 + 0.7*gs     # 0.3 → 1.0 × 23.5 Nm
command ranges            = 范围 × gs        # vx 以 0.5 锚定 ±1.0*gs，vy ±0.5*gs，yaw ±1.5*gs
reward terms              = 4 项里显式乘 gs   # forward / head_height / moving_y / moving_yaw
```

model_3000 训练到 `step_count = 24 × 3000 = 72000`，此时

```
gs = 0.789  →  179 Hz、20.0 Nm、vx ∈ [-0.29, 1.29]、vy ±0.39、yaw ±1.18
```

三种方案：

| 方案 | 问题 |
|---|---|
| 沿用 Gompertz、从 0 重新计时 | gs 掉回 **0.128**（113 Hz、7 Nm），预训练策略直接废掉 |
| 沿用 Gompertz、`--growth_step_offset 72000` 接着走 | 要再跑约 5 万步才到 0.95，这期间控制频率一直在漂，且永远到不了 1.0 |
| **恒等于 0.789** | 台阶需要满力矩（23.5 Nm）；而且 V54 现在实际是 gs≈0.99，两边不可比 |
| **0.789 → 1.0 线性 500 iter，然后冻结**（本方案） | 无跳变；500 iter 后与 V54 同一工作点（200 Hz、23.5 Nm、满命令域），语义也变干净：gs 只描述执行能力，不再影响奖励 |

实现见 `v55_growth.py`：

```python
gs(n) = 0.789 + (1.0 - 0.789) * min(n / 12000, 1)        # n = 策略步数（24 步/iter → 500 iter）
```

- 用 **策略步数** 而不是物理子步：频率在 ramp 过程中从 100 Hz 翻到 200 Hz，用子步会让时间表忽快忽慢。
  计数器放在 `V55ControlFreqEnv.step()`（每控制周期 +1）。
- **gs 有三个消费者**，必须同步：①`SataTorqueAction` 的力矩上限；②`SataVelocityCommand` 的命令范围；
  ③`SataControlFreqEnv.step` 的控制频率（→ decimation）。三者都通过模块级 `sata_growth_scale` 读取，
  所以 `v55_growth.py` 在 import 时把这个函数整体换成了 `v55_growth_scale`。
  如果只改动作项，实际会变成"20 Nm 却跑 113 Hz"（旧的 Gompertz 在 step 0 的值），预训练策略立刻失配——
  这是构建时抓到并修掉的一个坑，smoke test 里用 decimation 序列做了回归断言。
- `_v55_freeze_gs`：评估/回放必须钉住（默认 1.0），否则新进程从 0 起算会按 0.789 评估。
- 奖励侧 gs：V55 的奖励表里没有一项读 gs，天然消失。

## 4. 奖励表（与官方逐项一致）

| 项 | 权重 | 说明 |
|---|---|---|

| `track_ang_vel_z_exp` | +0.75 | `std=0.5` |
| `lin_vel_z_l2` | −2.0 | **无平地门控**，台阶上会罚垂直运动（约 −0.18 /s） |
| `ang_vel_xy_l2` | −0.05 | |
| `dof_torques_l2` | −2e-4 | V54 用的是 motor_fatigue，这里换成官方项 |
| `dof_acc_l2` | −2.5e-7 | V54 是 −1e-6（4×） |
| `action_rate_l2` | −0.01 | |
| `feet_air_time` | +0.01 / 0.5 s | 官方 stock，200 Hz 下接近 no-op |
| `flat_orientation_l2` | 0.0 | 官方 flat 版本才给 −2.5 |
| `dof_pos_limits` | 0.0 | 官方原值就是 0 |
| `undesired_contacts` | **None** | 按决定关闭（官方 Go2 rough 默认） |

SATA 的九项（forward / head_height / moving_y / moving_yaw / roll / soft_dof_pos_limits /
motor_fatigue / dof_acc(−1e-6) / lin_vel_z_flat_gated）全部置 None。

**三个已知的"坑"（不修，只看现象）**

1. `lin_vel_z_l2` 不再门控：爬台阶的竖直速度要吃 −2.0 × vz²，抬腿越猛越亏。
2. `undesired_contacts=None`：蹭台阶免费。V40–V49 那批"爬上去"很可能就是蹭出来的，V55 大概率会重演。
   → 若出现"能上但明显靠小腿蹭"，第一件事就是把它打开 −1.0（1 N，thigh+calf），而不是改别的。
3. `dof_pos_limits=0.0`：没有"关节不进极限"的连续梯度，只有 0.05 余量的硬终止兜底。

## 5. 训练配置

| 项 | 值 | 理由 |
|---|---|---|
| 环境数 / 种子 | 4096 / 1 | 与 V52、V54 完全一致，三条曲线可比 |
| 迭代 | **15000**（每 **1000** 存一次，共 15 个 ckpt、约 70 MB/run） | 与 V54 预算一致（首次探路用 5000，只跑到 229 iter，见 §8） |
| lr / schedule | **1e-3 / adaptive（desired_kl 0.01）——IsaacLab Go2 rough 默认值，未改** | 与 V52/V54/官方逐位一致；实际生效 lr 由 KL 控制器接管（见 §8），不是这个数字 |
| 优化器 | **Adam 重置（不恢复 SATA 的 `optimizer_state_dict`）** | 见下方说明；critic 是随机的、奖励尺度变了 ~11×，旧一/二阶矩都是错的量级 |
| `init_noise_std` | **1.0（IsaacLab 默认，保持不变）** | 只搬 actor 权重，探索尺度重新从默认值开始；要复现 SATA 的探索就用 `--sata_init_std`（单变量消融） |
| 其余 PPO | 同 V52/V54 | γ0.99、λ0.95、clip 0.2、entropy 0.01、24 步 |
| 地形 / 课程 / 终止 / 生成 / 观测 | 全部继承 V54 | 单因子对照 |

**为什么优化器重置、不恢复**

`load_sata_actor.py` 只搬权重（actor 的 8 个张量，不含 `std`），不看 `optimizer_state_dict`。SATA 里那份 state 的形状其实是**兼容**的（1 个 param group、17 个张量 = actor 8 + std + critic 8，`step=60000`，lr 已衰减到 4.44e-4 = 1e-3×1.5⁻²），所以这不是"做不到"，是"不该做"：

1. **critic 是全新的**：17 个张量里 8 个属于 critic，其 `exp_avg` / `exp_avg_sq` 对我们随机初始化的 critic 毫无意义。
2. **奖励尺度变了 ~11×**（SATA 约 25/s → V55 约 2.3/s）：Adam 的 `v̂` 与梯度平方成正比，用旧 `v̂` 配新梯度，等于把每步的有效步长在头几百次更新里打歪（该大的地方小、该小的地方大）。
3. **冷启动恰好是稳健的**：Adam 首次更新 ≈ `lr·ĝ/(√ĝ²)=lr·sign(ĝ)`，即每参数步长 ≈ lr、与损失量级无关——这正是"换了目标函数"时想要的；恢复旧 moment 反而把这个性质丢掉。
4. 那份 state 的 lr 是衰减后的 4.44e-4，而我们配置是 1e-3，恢复 = 旧矩 + 新 lr 的混合物。

结论：**权重 warm start + Adam 冷启动**。代价是头几次更新偏大，因此看 iter 1–50 的 `Mean value loss`、`Mean action noise std`（从 1.0 起、应缓慢变化）、`mean_ep_length`（不应塌到 <200）；真塌了再改用 `schedule=fixed` + lr 3e-4 重跑，而不是恢复旧优化器。

**adaptive KL 为什么"一来就触底"：IsaacLab 原样，不改**

- 环境里装的 `rsl-rl-lib 4.0.1`（pip 元数据 editable → `isaac_sac_setup/rsl_rl_sac`，即官方 `leggedrobotics/rsl_rl_sac`）中，`rsl_rl/algorithms/ppo.py` **没有任何 SAC 专属代码**（SAC 独立在 `sac.py`），PPO 就是 IsaacLab 用的那一份。
- 它的 `update()` 只有一个展平 generator（`storage.mini_batch_generator(num_mini_batches, num_learning_epochs)`），KL 自适应就写在这个循环体内（ppo.py L267–291），所以 **每个 iteration 执行 20 次**（5 epochs × 4 minibatches），不是 1 次。
- 因此 lr 轨迹由 KL 控制器决定而不是配置值：warm start 的第 0 个 iteration 会一路 /1.5 撞到下限 1e-5，之后 ×1.5 回升（实测见 §8）。同一处代码在 SATA 的 rsl_rl 1.x 里也是 mini-batch 内，属于上游语义，**不是 SATA 带进来的**，故不改。

## 7. 怎么看结果（判定标准）

| 观察点 | 结论 |
|---|---|
| iter 100–500：`track_lin_vel_xy_exp` 恢复到 0.8 以上、`mean_ep_length` > 800 | actor 承受住了尺度切换，warm start 有效 |
| gs 升到 1.0 前后（iter 500）`base_contact` 不反弹到 >0.5 | ramp 没有造成失稳；否则应把 `gs_ramp_steps` 拉长到 2000 iter |
| `Curriculum/terrain_levels` 上不去（长期 <1），但 `forward` 速度正常 | 官方判据本身（升级 4 m / 降级 5×‖cmd‖）在限制，不是策略问题——和 V54 同一个坑 |
| 能上台阶但 `Episode_Termination/fell_over` 高、`lin_vel_z` 罚项大 | 官方奖励表与"抬腿上台阶"的冲突显性化，此时再讨论加回门控 |
| 完全学不会上台阶 | 说明 2.3/s 的稀疏正项不足以支撑探索 → 这是本实验要给出的结论，不要再往奖励里堆 SATA 项 |

## 8. 已验证（2026-10-24，GPU0）

- `smoke_test.py --sata_init model_3000.pt`（默认不搬 std）→ `=== SMOKE TEST PASSED ===`：
  奖励 10 项有效（+2 项权重 0）逐项相符，`undesired_contacts` 不在表里；
  终止 = `time_out / base_contact / dof_pos_limit / fell_over`；
  gs 起点 0.7891 → 20.03 Nm / 178.9 Hz；gs(6000)=0.8946、gs(12000)=1.0000；
  `_v55_freeze_gs=0.95` 生效；`copied 8 tensors`，
  `std (kept at init_noise_std): min=1.000 mean=1.000 max=1.000`；
  **频率随 gs 走**：gs=1.0 → decimation 恒为 1（200 Hz）；gs=0.789 → 24 步里出现 2，均值 1.125（≈179 Hz，与 SATA 的进位循环一致）。
- `smoke_test.py --sata_init ... --sata_init_std` → `copied 9 tensors`，
  `std (from checkpoint): 1.476/2.307/3.104`，且与 checkpoint **逐元素相等**（`torch.equal`）。
- `train.py --sata_init ... --num_envs 1024 --max_iterations 3`（默认 std=1.0）：
  `Mean action noise std: 1.00`（三 iter 不变），`Mean reward −0.10 → −0.10 → −0.11`，
  `terrain_levels 2.553 → 2.532`，`fell_over` / `base_contact` 均为 0；
  作为对照，加 `--sata_init_std`（std 2.31）同规模：`Mean reward −0.25 → −0.44 → −0.64`，大噪声更伤。
- `evaluate.py --checkpoint model_100.pt --num_envs 16 --steps 60` → 正常输出每项奖励（per step / per s）、
  地形等级、gs 与力矩；100 iter 的策略 `track_lin 1.10/s`、`track_ang 0.55/s`、`lin_vel_z −0.76/s`（无门控，符合预期）。
- 优化器确实重置（从 2 iter 的 `model_2.pt` 反查）：Adam `step=40`（=2×5 epochs×4 minibatches）vs SATA 的 `60000`；
  17/17 个 `exp_avg_sq` 与 SATA 全不相同；同时 actor 最大位移 0.0061（说明确实在更新）。
- **实际 lr 不遵配置值**（1024 envs、3 iter，`Loss/learning_rate`）：
  默认 std=1.0 为 `1e-5 → 7.59e-5 → 1.71e-4`；`--sata_init_std` 为 `1e-5 → 1.71e-4 → 5.77e-4`。
  两者都在第 0 个 iteration 被连压到下限，说明触底与 std 大小无关，只来自 per-mini-batch 的 KL 检查 + warm start。
  看 lr 只能看 tb `Loss/learning_rate` 或 checkpoint 的 `param_groups[0]["lr"]`。
