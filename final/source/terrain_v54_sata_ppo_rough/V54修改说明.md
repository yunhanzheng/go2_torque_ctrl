# V54 修改说明（2026-10-22）

V54 的基线是 V52：SATA `go2_torque` 的 9 项奖励、60 维观测、TG 力矩模型、Gompertz 成长
课程、SATA 出生姿态与终止集、PPO。V54 只把地形换成 IsaacLab 官方的 Go2 rough
（`ROUGH_TERRAINS_CFG`）。

本文档记录在此基础上做的四组修改，全部改动集中在
`terrain_v54_sata_ppo_rough/config.py` 与 `smoke_test.py`。

> 除上述四组外，V54 相对 V52 还有两项基线差异：地形本体从 SATA 的
> `sata_smooth_slope` / `sata_rough_slope` 换成官方 `ROUGH_TERRAINS_CFG`；
> `self.events.sata_joint_limits = None`，把 SATA 的正向大腿限位窗
> （前 `[0, 1.5]`、后 `[0, 2.0]`）换回 Unitree USD 原始范围——默认站姿 1.45 rad
> 落在 SATA 90% soft bound（1.425）之外，小腿只剩 0.128 rad 行程，迈不上 23 cm。

## 1. 奖励项：9 → 12

补齐官方 Go2 rough 阵容里的 3 个正则项。V52 把继承来的奖励项全部置为 `None`，这 3 项等于从零添加。

| 项 | 权重 | 作用 | 备注 |
|---|---|---|---|
| `ang_vel_xy_l2` | -0.05 | 惩罚 roll/pitch 角速度 | `roll` 只看角度，控制器可以高速来回穿过水平面而不受罚 |
| `action_rate_l2` | -0.01 | 关节目标的一阶差分 | SATA 完全没做，靠 `motor_fatigue` 隐式平滑；这里是廉价保险 |
| `feet_air_time` | +0.01 | 摆动时长超过 `threshold` 的脚落地时给奖励 | threshold = 0.5 s，与两套官方实现一致 |

配套新增脚部接触传感器（`feet_air_time` 需要 `track_air_time`）：

```python
self.scene.feet_contact = ContactSensorCfg(
    prim_path="{ENV_REGEX_NS}/Robot/.*",
    history_length=3,
    track_air_time=True,
    debug_vis=False,
)
```

`threshold = 0.5 s` 高于 Go2 名义小跑摆动（约 0.2 s），因此该项在落地的每一步给出
`(0.2 - 0.5) = -0.3 s` 的负值——它实际上是一个「站罚」，梯度指向更长、更高的摆动，
正是 23 cm 台阶需要的。实测随机动作下 raw 值在 `-0.25 ~ 0.0` 之间。

最终 12 项奖励：

```
forward(10) head_height(5) moving_y(5) moving_yaw(5) motor_fatigue(-0.05)
roll(-5) lin_vel_z_l2(-5) soft_dof_pos_limits(-5) dof_acc(-1e-6)
ang_vel_xy_l2(-0.05) action_rate_l2(-0.01) feet_air_time(0.01)
```

## 2. head_height：参考从「世界水平面」改为「前后脚地面点连线」

### 旧逻辑（V52 / V51）

1. `base_clearance`：取离基座 xy 最近的那条高度射线，`root_z - ray_z`，clip 到 0.3 m；
2. `head_up`：`-max(g_b[0], 0)`，以**世界水平面**为基准只罚低头；
3. 前一版给整个项加了「四脚附近地形落差 < 1 cm」的平地门控。

问题是：上台阶时机体必须抬前身，而参考面始终水平，低头惩罚会和地形对抗。

### 新逻辑

参考面由**前后脚脚下的地面点**定义：

```python
z   = foot_ground_height(env, feet_cfg)              # 每只脚最近的一条竖直射线 [N,4]
zF  = z[:, :2].mean(1);  zR = z[:, 2:].mean(1)       # 前脚 / 后脚
slope = atan((zF - zR) / 0.3868)                     # 目标俯仰，上坡为正
dist  = (root_z - 0.5 * (zF + zR)) * cos(slope)      # 基座到该连线的垂距
g_rel = -sin(base_pitch - slope)                     # 相对地形线的重力投影
head_up = -g_rel.clip(min=min(0.0, -0.2 * (1.5 - 2.0 * gs)))
head_height = dist.clip(max=0.3) * (1.0 + gs) + head_up
```

要点：

| 细节 | 取值 | 理由 |
|---|---|---|
| 前后点间距 | 常数 `0.3868 m`（= 2 × 髋 x 0.1934） | 用瞬时脚位投影会把步态相位噪声灌进斜率（实测 0.2–0.5 m 摆动） |
| 每只脚的地面高度 | 离该脚 xy 最近的栅格射线 | 射线网格焊在基座上，无法从摆动的脚上单独发射；最近格点误差 ≤ 半格 ≈ 5 cm |
| 无有效射线时 | 回落到底座下方有效读数的均值 | 单条射线缺失不会把参考线掀翻 |
| `slope_tau` | 0.3 s 一阶低通（滤 `zF/zR`，不滤角度） | 脚跨过台阶棱线时采样值整级跳变，会在奖励里注入与动作无关的 31° 方波 |
| 平地门控 | **已移除** | 参考线本身就是地形，坡道/台阶上不需要再区分 |
| 俯仰上限 | **无**（`g_rel` 天然限在 ±1） | SATA 原版就没有下限截断；低头 90° 对应 −1 |

`head_up` 是 SATA `go2_torque._reward_head_height` 的**原形状**，只把零点从「水平」搬到
「地形线」——即把 `g_x` 换成 `-sin(pitch − slope)`。平地上两者逐位相同：

- 相对地形线**仰头**：正奖励，封顶 `0.2 × (1.5 − 2·gs)`，到 `gs = 0.75` 归零；
- 相对地形线**低头**：负惩罚，无上限；
- 23 cm 台阶上站立 `lag = -31°` → `head_up = -0.5`，抬头到楼梯坡度即可回到 0 并拿到封顶奖励。

### 低通实现

```python
def _lowpass(env, key, value, tau):
    store = env.__dict__.setdefault("_reward_lowpass", {})
    if tau <= 0.0:                     # 关闭开关
        return value
    buf = store.get(key)
    if buf is None or buf.shape != value.shape:
        buf = store[key] = value.clone()
        return buf
    fresh = env.episode_length_buf <= 1     # 刚 reset 的行用当前读数重播种
    buf[fresh] = value[fresh]
    buf.add_((value - buf) * (1.0 - math.exp(-env.step_dt / tau)))
    return buf
```

`α = 1 − exp(−dt/τ)` 与步长解耦，改控制频率不用重调；`slope_tau = 0` 即关闭滤波。

## 3. lin_vel_z：加平地门控

```python
def lin_vel_z_on_flat(env, asset_cfg, feet_cfg, radius=0.15, max_relief=0.01):
    on_flat = on_flat_ground(env, feet_cfg, radius, max_relief).float()
    return env.scene[asset_cfg.name].data.root_lin_vel_b[:, 2].square() * on_flat
```

- 式子与权重（`v_z²`，-5）和 SATA 完全一致，唯一区别是乘了一个 0/1 掩码；
- 掩码：四只脚各自 15 cm 半径内的射线高度差（`amax − amin`）都 < 1 cm 才算平地；
- 理由：23 cm 台阶上机体**必须**上下移动，无门控的 `v_z²` 纯粹是阻力；平地仍保留抑振；
- 无有效射线的脚判为「非平地」，不给解锁罚项。

奖励项同时从 `lin_vel_z` 改名为 `lin_vel_z_l2`（`self.rewards.lin_vel_z = None`），
以反映它是 `v_z²` 而非 `|v_z|`。

## 4. 地形课程：对齐官方

| 项 | 官方 `UnitreeGo2RoughEnvCfg` | V54 改前 | V54 现在 |
|---|---|---|---|
| `curriculum.terrain_levels` | `terrain_levels_vel` | 有（V52 设 None，V54 已恢复） | 有 |
| `generator.curriculum` | True | **False** | **True** |
| `max_init_terrain_level` | 5（`MySceneCfg` 默认） | 5 | 5 |
| `generator.seed` | None | 42 | 42（保留固定种子） |

关键是第二个：课程需要「调度 + 生成」两件套。只有 `terrain_levels_vel` 而
`generator.curriculum = False` 时，每一行的难度是随机抽的，升级只是换一块随机 tile。

现在难度随行号线性增长：

```
difficulty = lower + (upper - lower) · (row + U(0,1)) / num_rows
step_height = 0.05 + 0.18 · difficulty
```

| 行 | 台阶高度 |
|---|---|
| 0 | 5.0 – 6.8 cm |
| 5 | 14.0 – 15.8 cm |
| 9 | 21.2 – 23.0 cm |

调度规则（`terrain_levels_vel`）：

- 走出 `size[0]/2 = 4.0 m` → 升一行；
- 走得不足 `‖cmd‖ × 10 s × 0.5` → 降一行；
- `level ≥ 10` → 随机重投到 0–9 行；
- 初始 `randint(0, 6)` → 0–5 行，第一回合不会正对 23 cm 台阶。

注意：指令上限随 `gs` 缩放为 `1.5·gs`，而升级门槛固定 4 m。`gs = 0.128` 时 10 s 内
最多走 1.92 m，升不了级；要等 `gs ≈ 0.27`（约 15k 物理步）才可能开始爬课程。前期
训练实际集中在 0–5 行（5–15.8 cm）。

- `terrain_levels_pit_first` 替掉 `terrain_levels_vel`：
  - -1 档的 env 走满 4 m → **直接跳到 0 档**（行 10，5.0–6.8 cm），
    不逐行爬（坑的那 10 行几何完全一样，逐行爬只是浪费 episode）；
  - 到 0 档后恢复原来的 ±1 档升降，但 **下限锁定在 0 档** —— 再也回不到 -1；
  - 从 9 档再升级 → 随机落到 0–9 档（原版会随机到 0–19 行，会把 env 扔回坑）。
- 为什么坑要占 10 行而不是 1 行：env 是按 (行=难度, 列=类型) 铺的，1 行只有 20 个 tile，
  4096 个 env 会挤成 205 个/tile（=当前密度的 10 倍），出生点直接重叠。10×20 = 200 个
  坑 tile 才能保住 ~20 env/tile。代价是网格从 200 个 tile 变 400 个（几何量翻倍）。

启动：`TASK=Isaac-Go2-V54-PitFirst-v0 LOG_TAG=V54_pit_first bash run_trial.sh`
（`run_trial.sh` 新增 `TASK` / `LOG_TAG` 两个环境变量，默认值就是原 V54）。

**坑（2026-10-24 实测踩到并修掉）**：`ManagerBasedRLEnv._reset_idx` 里课程项是在
`scene.reset()` / 出生事件**之前**调用的，所以 t=0 那次 compute 读到的是出生前的
`root_pos_w`（与 tile 原点差 6–109 m，64 人全部 > 4 m）→ 所有人被一次性推出 -1 档，之后
被下限锁在 0 档再也回不去，日志里 `Curriculum/terrain_levels` 会直接显示 ≈0（例如
`-0.0017`）而不是 `-1`。修法：课程项里用 `env.episode_length_buf[env_ids] > 0` 只判定
真正跑过一步的 env。验证：64 env 实测 `env.reset()` 后 `levels` 仍是 0–9、
`Curriculum/terrain_levels = -1.0`。

注意：观测、动作、奖励、终止、Gompertz 曲线、PPO 超参均未动；坑底的出生高度仍为
0.10 m（地形原点 z = −0.35 m，环境原点随之下降）。

## 9. 2026-10-25 rev E：课程升不上去 —— 降级逻辑删掉 + 转向随等级放开

### 9.1 现象

`2026-10-24_21-46-46_V54_pit_first_20261024T134634Z` 跑满 15000 轮，
`Curriculum/terrain_levels` 只有 **0.356**（开局 −1，2 秒内爬出坑之后就基本躺平）：
`Mean episode length 1577/4000`、`Mean reward 63.83`。更早的 pit run 也一样。

### 9.2 根因：判据是「净位移」，指令却在转圈

`terrain_levels_vel` 的升级线是
`distance = ‖root_pos_w[:2] − env_origins[:2]‖ > size[0] / 2`：

- **4 m 的定义** = 半个瓦片（`ROUGH_TERRAINS_CFG` 的 `size=(8, 8)`，V54 没改），测的是
  **回合结束那一瞬**机器人离瓦片原点的**直线位移**，不是路程，也不是「跨过瓦片边界」。
- 降级线是 `distance < ‖v_cmd[:, :2]‖ · episode_length_s · 0.5`（旧代码），10 s 回合下
  等于 `5·|v|`，满速 1.58 m/s 时 **7.9 m，比 4 m 的升级线还高** → 存在「3.9 m 不给升、
  5.5 m 又判降」的区间。
- SATA 的采样器给 `ang_vel_z ∈ ±1.5`（`resample 5 s`，10 s 回合里两条独立指令）：0.5 m/s
  时转弯半径 0.33 m，10 s 能画好几圈；`wz` 既不进 `distance`，也不进降级的 `‖cmd‖`
  （那里只取 `vx, vy`）。

理想跟踪（完美执行指令、全程不摔）的蒙特卡洛，40 万回合：

| 指令 | P(升级) | P(降级) | 中位位移 | 中位路程 |
|---|---|---|---|---|
| 现状 `wz ±1.5` | **26.9 %** | **56.2 %** | 2.37 m | 7.03 m |
| `wz ±1.5` 且 `\|wz\|>0.8` 的回合（占 44 %） | 9.1 % | 81.3 % | — | — |
| `wz ±0.4` | 63.4 % | 15.7 % | 5.06 m | 7.03 m |

也就是说：**跟着指令走也升不了级**，课程被降级主导，稳在 0 档附近（用上面的概率跑
4096 env × 15000 迭代的地板随机游走，复现出 0.86，与实测 0.356 同量级）。

### 9.3 改动（两处，都不碰奖励表）

1. **转向范围随地形等级放开** — `SataVelocityCommandCfg.level_scaled_yaw`（默认 False，
   只有 V54 / V54-PitFirst 打开）：
   `wz_max = 1.5 · clamp((level − level_offset) / level_ref, 0, 1)`，`level_offset` 对
   pit 任务是 `PIT_ROWS`（10），`level_ref = 9`（最高档）。效果：坑里和 0 档直线走
   （升级率 ~67 %），2 档 ±0.33、4 档 ±0.67、6 档 ±1.0、9 档 ±1.5（SATA 满量程）。
2. **删掉降级 + 到顶冻结课程** — `terrain_levels_promote_only`（V54）与
   `terrain_levels_pit_first`（pit）里不再有 `move_down`，等级只增不减；最后一档改成
   `clamp(max_terrain_level)` 的**不动点**（不再用官方的 `levels >= max → randint`），
   即“到了最高等级就把课程关掉”，该 env 之后就一直在最难地形上练，同时吃满 ±1.5 的转向
   指令。**档位随机化不存在**：难度（行）单调上升，地形类型（列）始终不变。
   `ran`（`episode_length_buf > 0`）保护保留。

V51 / V52 / V53 不受影响（`level_scaled_yaw` 默认关，它们也没有装课程项）。

### 9.4 验证

命令探针（32 env，`_sata_freeze_step_count=300000` 把 gs 钉到 0.9997）：

### 9.5 注意

- 改的是课程 / 指令管线，**奖励表、观测、动作、终止、PPO 超参都没动**；`ang_vel_z` 的

- 必须重启训练才生效（课程项在 env 构造时绑定）；与 rev A–D 的 run 不可直接比较，
  它们的课程一直卡在 0 档。
- 没有降级、没有随机重投 = **等级单调上升，到最高档就冻结**：所有 env 最终都会停在
  9 档（pit 任务是 row 19），之后课程等于自动关闭。用 rev E 的升级率
  （随等级 67 %→27 %）仿真，约 40 个回合后全部到顶；想再看低档样本只能靠重启

  没有 env 退到低档做保底样本。若后期发现高档次崩得历害，把 `level_ref` 调小
  （例如 6，让转向更早满量程）或恢复一个“连续 N 回合 < 1 m 才退一档”的软降级即可。

## 10. 2026-10-25 rev F：按地形类型分项看指标 + 两个课程 bug

### 10.1 为什么只看平均不够

`Curriculum/terrain_levels` 是 4096 个 env 的一个标量平均，`Episode_Termination/*` 又是
**所有 env、所有地形** 混在一起的每步均值。两种地形的问题会互相抵消：楼梯上摔一半、
random_rough 上几乎不摔，平均曲线看起来“还行”，但楼梯那一半其实是白跑的。所以要看
**每种地形自己的**曲线。

### 10.2 新增 `Curriculum/by_type/<指标>/<地形>`（纯日志，不改状态）

`pit_terrain.episode_stats_by_terrain_type()`，注册成课程项 `by_type`（`log_episode_stats_pit`
/ `log_episode_stats_stock`）。每个**刚结束的回合**按地形分桶，每桶 8 个指标：

| 指标 | 含义 |
|---|---|
| `n` | 这个地形这一批结束了几个回合（样本量，样本 < 10 时曲线会很抖） |
| `level` | 这些回合**实际上是在哪一档跑的**（display level，坑是 -1） |
| `len` | 回合长度（policy 步，和 `Train/mean_episode_length` 同单位） |
| `ret` | 回合累计奖励（`_episode_sums` 求和，未归一化） |
| `dist` | 回合结束时离出生点的**净位移**（m）——就是课程升级判据的那个量 |
| `fall` / `timeout` / `dof` / `base` | `fell_over` / `time_out` / `dof_pos_limit` / `base_contact` 的**发生率** |

分桶规则：6 个子地形按列映射（20 列 → 4/4/4/4/2/2），另加一个 `pit` 桶。坑的 10 行也是
按列铺的，不单独拆出来会被算进它并不属于的地形里。

三条约定：
1. 是**比率不是计数**，且**只统计已结束的回合**。子地形的列数不一样（4 vs 2）；如果按
   每步全体均值算，99 % 的 env 都在回合中间，信号会被冲没。
2. 必须**在 reset 之前读**：`ManagerBasedEnv._reset_idx` 先跑 curriculum，再 `scene.reset`，
   所以 `episode_length_buf` / `RewardManager._episode_sums` / `TerminationManager._last_episode_dones`
   这时还都是“这一回合的终值”。
3. 课程项**按 config 属性顺序执行**，而升级项会改写 `env_origins`（`dist` 的基准），所以
   `by_type` 必须排在 `terrain_levels` **前面**。父类已经定义了 `terrain_levels`，普通赋值
   只会排在它后面，因此 `__post_init__` 里重建了 `curriculum.__dict__` 的顺序。

读数提醒：各类型的 env 是各自晋级的，爬得快的地形同时也在跑更高的档，所以**看比率时要
一起看 `level`**。想比较“同一难度下谁更难”，得等大家都爬到 9 档（rev E 之后约 40 个回合）。

### 10.3 bug 1（严重）：policy 第 0 步就把坑清空了

`2026-10-24_21-46-46` 里 `Curriculum/terrain_levels` 只在 **pre-step** 那一条是 -1.0。探针实测
（`/tmp/probe_trace.py`，8 envs，零动作）：

```
--- step 0
  [term] buf=[1,1,1,1,1,1,1,1]  dist=[98.24, 68.99, 43.07, ...]
         root=[[3.75,-1.25], [3.75,1.25], ...]        # 预放置网格
         origin=[[-60,-76], [-28,-60], ...]           # 真正的瓦片原点
  rows after: [10, 10, 10, 10, 10, 10, 10, 10]
```

原因：`SataControlFreqEnv._sata_substep_step` 在 substep 循环**之前**先
`episode_length_buf += 1`，所以第一个 policy 步就已经 `buf == 1`，原来的
`ran = episode_length_buf > 0` 挡不住；而机器人这时还停在预放置网格上（把它们放到瓦片上的
`scene.reset` 发生在同一个 step 的 `_reset_idx` 末尾），`root_pos_w` 离瓦片 20–100 m →
`distance > 4 m` 对全部 4096 个 env 成立 → pit 被一次性清空。

修法：`ran = (episode_length_buf > 0) & (common_step_counter > 1)`，两个课程项都改。
`common_step_counter` 也是在 substep 循环前 +1，所以第一个 policy 步等于 1，正好被挡住；
之后完全等价于原来的语义。`episode_stats_by_terrain_type` 在 `common_step_counter <= 1`
时直接返回 `{}`，否则第一次迭代的 `dist` 会有个 20–100 m 的尖峰。

### 10.4 bug 2：爬到顶档会越界

`terrain.max_terrain_level` 是 `num_rows`（`TerrainImporter._compute_env_origins_curriculum`），
而 `terrain_origins` 只能索引 `0 .. num_rows-1`。rev E 里写成
`clamp(levels + move_up, max=max_terrain_level)`，env 从最后一档再升一级就变成 `row = 20`
（pit 网格）/ `row = 10`（stock 网格），`terrain_origins[20]` 直接 IndexError——也就是
**第一个 env 爬到 9 档的那一步，训练会崩**。改成 `max_terrain_level - 1`，顶层成了真正的
不动点（stock 的写法是 `levels >= max` 就重投，所以它没这个问题）。

### 10.5 验证

- 桩环境单测（`/tmp/by_type_test.py`，不需要 Isaac）：列→地形映射、分桶、比率、
  `n`、pit 与 stock 的拆分、退化的 termination 项、异常兜底，全过。
- 真机探针（`/tmp/probe_verify.py`，8 envs）：step 0 有 8 个回合结束但
  `rows` 保持不变、`Curriculum/terrain_levels = -1.0`；把机器人挪到离原点 5 m 再调用课程项 →
  全部 `row 10`（level 0，正确晋级出坑）；把 `terrain_levels` 置到 19 再调用 → 仍是 19，
  不再 IndexError。
- `python3 -m py_compile config.py pit_terrain.py` 通过；两个 cfg 的 `validate()` 通过，
  `curriculum` 顺序为 `['by_type', 'terrain_levels']`。

### 10.6 影响

- 奖励表、观测、动作、终止、PPO 超参都没动；新增的只是日志（`by_type` 每次 reset 多两次
  GPU 同步）和上面两个课程 bug 的修法。
- 与 rev A–E 的 run 不可直接比较：那些 run 的 pit 实际上从没用上（第 0 步就出坑了），

- 按 rev F 跑，开局 `Curriculum/terrain_levels` 应该是 **-1.0 并且维持到第一批回合结束**

## 11. 2026-10-25 rev G：降级回来，只有到顶才冻结

### 11.1 rev E 改过头了

rev E 把降级的**两半**（判据和被调用的动作）一起删了，语义变成"整段课程只升不降"。
实际要的是：**爬升阶段照常升降**（撑不住就该掉一档，这是课程的本意），
**只有爬到最高档之后才不再下降**，并且到顶后转向恢复到 SATA 默认。

### 11.2 现在的规则

| | 爬升阶段（level 0–8） | 到顶（level 9） |
|---|---|---|
| 升 | 净位移 > `size[0]/2` = 4 m → +1 档 | 不再动（`clamp(max=top_row)`，死路） |
| 降 | 净位移 < `\|v_cmd_xy\| × max_episode_length_s × 0.5`（默认值即 5 m @ vx=1）→ −1 档 | 不再动 |
| 转向 | `ang_vel_z` 幅度 = `level / 9 × ±1.5` | **= ±1.5，与 SATA 默认完全一致** |

三条实现约定：

1. **判据用 IsaacLab 原生公式**，只是补了两个原生没有的保护：
   - `ran = (episode_length_buf > 0) & (common_step_counter > 1)` —— 挡住"出生前/第 0 步"
     的伪位移（原生在 t=0 会把整批 env 判一遍）；
   - 到顶用 `clamp` 冻结，而不是原生的"随机重投"（`TerrainImporter.update_env_origins`
     会把爬到顶的 env 扔回随机行，等于把爬升成果扔掉）。
2. **pit 档是一去不回的**：坑里没有更低档，所以坑内只升；出坑后 `min=PIT_ROWS`，
   降级最多回到 level 0（row 10），**不会退回坑里**。
3. **`ang_vel_z` 不进降级判据**：原生用的是 `command[:, :2]`，只取 x/y。所以"给转圈命令"
   本身不会直接触发降级，转圈造成的**净位移变小**才会。

`sata_alignment.py` 里的默认采样是 `ang_vel_z=(-1.5, 1.5)` **均匀随机**，再乘 SATA 的
Gompertz `gs`；它**不随地形等级变化**。所以"到顶恢复默认"= `k = level/9` 在 9 档取到 1.0，
不需要额外开关，爬升期与到顶之间也没有命令分布的突变。

### 11.3 改动位置

- `pit_terrain.py`
  - 新增 `_stock_move_flags(env, env_ids, asset_cfg, ran)`：原生的 `move_up` / `move_down`
    两个判据，`ran` 折在里面；`move_down &= ~move_up` 与原生一致。
  - `terrain_levels_promote_only` → 重命名为 **`terrain_levels_top_freeze`**，恢复降级，
    只保留"到顶死路"这一处与原生不同。
  - `terrain_levels_pit_first`：坑内仍只升；stock 段改成原生升降 +
    `clamp(min=PIT_ROWS, max=top_row)`。
- `config.py`：import 与引用改名，文件头新增 rev G 说明，rev E 那段补一句"rev G 把降级加回来了"。
- `terrain_v51_native_terrain/sata_alignment.py`：**未改**（`level_scaled_yaw` 的线性语义不变）。

- 与 rev A–D 也不可比：转向被按等级限制，且第 0 步误判已修。
- 验收点（新 run 第 1 个 iteration 之后）：
  1. `Curriculum/terrain_levels` 从 **-1.0** 开始，且第 1 轮不动；
  2. 之后**会上下波动**（有降级了），不是单调上升；
  3. `Curriculum/by_type/level/*` 在 6 个地形桶上分别给出曲线，`pit` 桶单独一条；
  4. 观测量级上，越靠后的档位 `ang_vel_z` 越接近 ±1.5（`Policy/mean_noise_std` 无关）。

## 12. 2026-10-25 rev H：critic 变特权，加 187 维高度图

### 12.1 之前 critic 没有特权信息

`observations` 里只有 `policy` 一个组（60 维、带每通道噪声、带 10% 保持上一帧）。
rsl_rl 的 `resolve_obs_groups` 找不到名为 `critic` 的组就 fallback 回 `policy`，
所以 actor 和 critic 吃的是**同一份带噪声的张量**，critic 只是不决定动作，信息量并不更多。

### 12.2 现在

| | 组 | 维度 | 噪声 / 丢帧 |
|---|---|---|---|
| actor | `policy`（未改） | 60 | 每通道均匀噪声 + 10% 保持上一帧 |
| critic | `critic`（新增 `CriticObsCfg`） | **247** = 60 + 187 | **无** |

- 60 维部分与 policy 同来源，但走 `sata_observation_60d`（干净版，不叠噪声、不丢帧）。
- 187 维是 `mdp.height_scan`：`height_scanner` 以 base 为中心、1.6 m × 1.0 m、0.1 m 栅格
  → 17 × 11 = 187 根竖直向下的射线，`clip=(-1, 1)` 与官方 Go2 rough 一致。
  `height_scan` 减掉 `offset=0.5`（名义安装高度），所以**平地读数约 -0.2**、23 cm 台阶面
  约 +0.03 —— 含义是「base 到该格地面的高度减 0.5 m」。
- 这个 scanner 本来就在场景里（奖励项的 `foot_ground_height` / `foot_terrain_relief` 一直在读
  `ray_hits_w`），**没有新增传感器**，只是把同一份数据也喂给 critic。

### 12.3 改动位置

- `config.py`
  - 新增 `CriticObsCfg(ObsGroup)`：`base_lin_vel = ObsTerm(func=sata_observation_60d, clip=±5)`
    + `height_scan = ObsTerm(func=mdp.height_scan, clip=±1)`，`enable_corruption = False`。
  - `V54SataPpoRoughEnvCfg.__post_init__`：`self.observations.critic = CriticObsCfg()`。
  - `V54SataPpoRoughRunnerCfg.__post_init__`：`obs_groups = {"actor": ["policy"], "critic": ["critic"]}`。
  - 文件头新增 rev H 一节。
- `train.py`：新增 `--init_actor_only`（见 12.5）。
- `smoke_test.py`：断言 `obs_groups` 映射、critic 维度 247、critic 无 nan，并打印高度图量级。
- pit 任务自动继承（`V54PitFirstEnvCfg` / `V54PitFirstRunnerCfg` 走 `super()`）。

### 12.4 没变的东西

- **actor 网络、它的输入宽度、部署行为都不变**：60 维照旧，只是训练时多了一个更宽的 critic。
  rev H 训出来的策略照样能直接上真机，与 rev G 完全一致。
- 奖励表 / 终止 / 动作 / PPO 超参 / 地形 / 课程都没动。
- 高度图的加入让 `height_scanner` 从「只被奖励读」变成「也进观测」，更新周期仍是
  `decimation * sim.dt`（与官方一致）。

### 12.5 热启动注意

旧 checkpoint 里 critic 第一层是 `Linear(60, ...)`，rev H 是 `Linear(247, ...)`，
而 `runner.load()` 默认 `strict=True`，直接 `--init_from` 会在 size mismatch 上抛错。
train.py 因此加了开关：

```bash
--init_from <ckpt> --init_actor_only
```

它只加载 actor（以及 iteration 计数），critic 与 Adam 状态从头开始 —— 这是唯一可行的组合，
因为 Adam 的 state 绑定在两个网络上（一并加载必然尺寸不匹配）。

### 12.6 验收

1. 启动日志出现 `Observation Manager contains 2 groups`，以及
   `Resolved observation sets: actor: ['policy'], critic: ['critic']`；
2. 网络摘要两行：`Actor ... Linear(in_features=60, ...)`、`Critic ... Linear(in_features=247, ...)`；
3. `smoke_test.py` 打印的 `height scan: min/max/mean` 应在 -1..1 内、平地均值约 -0.2；
4. 与 rev G 的 `Loss/value_function` 不可直接比：critic 现在看的东西更多，value 拟合目标变好。
